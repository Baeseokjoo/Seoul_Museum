## 2. 프로젝트 정보

- **제작 기간**: 2026.11.06 ~ 2026.11.09 (04일)
- **담당 역할**: 개인 프로젝트 (기여도 100%)
- **담당 범위**: Figma 개선 디자인 → 바이브코딩 구현 → GitHub Pages 배포

## 3. 사용 기술

- **React, Vite**: Figma 디자인에서 구성한 컴포넌트를 그대로 구성해 화면을 컴프넌트로 구현하고 쉽게 수정할 수 있기 위해 사용.
- **GitHub Pages**: 무료 배포
- **Figma**: 개선 디자인
- **Claude**: 바이브코딩 (화면 구현)

## 4. 주요 기능

- 메인 페이지의 NAV를 상단으로 배치 및 메뉴 재구성
- 모바일 데스크탑 반응형 레이아웃 구성
- 원하는 정보를 얻을 수 있는 전시 해설 일정찾기 검색 기능

## 5. 트러블슈팅

### 이슈 1: 일정이 존재하지 않을 경우 나타나는 화면 구성이 없다.

- **문제**: 조회된 날짜 이후로 일정이 없을 경우 '가장 가까운 날짜로 조회하기' 버튼을 클릭하더라도 화면이 변하지 않았음.
- **원인**: '가장 가까운 날짜로 조회하기' 버튼은 처음 조회된 날짜 이후 일정이 있을 경우 가까운 날짜로 자동 검색이 되는 기능을 가지고 있지만 일정이 없을 경우 나타나는 상태를 구성하지 않았기 때문이다.
- **해결**: 결과가 존재하지 않을 경우의 팝업창을 Claude를 이용해 Figma 완성본에 모바일과 데스크탑으로 반응형되는 팝업창을 새로 구성하도록 요청 후 기존 컴포넌트를 활용해 디자인 및 구현까지 처리함.

## 6. AI 활용 방식

- **맡긴 일**: Figma에서 활용한 컴포넌트를 React로 구성해 화면 구현
- **핵심 프롬프트**: "[Figma에서 구성한 컴포넌트 링크]색상, 간격, 폰트 등은 반드시 tokens.css에 등록된 것을 하용하고 파일의 이름은 컴포넌트와 이름을 같도록 만들어줘. 의존성관계를 고려해서 순서대로 만들어줘. 이미지는 png,jpg로 다운로드 해서 작성해줘."

## 7. 회고

- **배운 점**: Figma에서 구성한 디자인을 그대로 구현하기 위해서 HTML,CSS,JavsScript로 서로 연결이 되며 구성이 되어진다는 것을 알게 되었으며, 디자인에서 구현처리 시 어떠한 방식으로 구현이 될 지, 반응형은 어떠한 방식으로 처리가 되야할지 확실하게 정해져야 수정이 필요할 경우 수정을 더 원활하게 보다 쉽게 할 수 있음. 또한 AI를 활용해 구현을 실행시킬 때에 프로토타입, 레이아웃, 등 내가 정한 방향대로 구현이 되고 있는지 체크를 해가면서 한 번에 많은 양을 처리하기보다는 작은 단위의 구성을 밟아나가며 진행해야 본인이 정한 개선방향을 나타낼 수 있음.
- **아쉬운 점**: Figma에서 데스크탑 기준 화면 구성을 1920px로 디자인을 하게 됨으로써 구현이 되었을 때 좌우 공백이나 메인페이지의 Header영역이 화면을 넘어가 보여지게 되어 전체적인 사이즈 구성이 아쉬웠음. 데스크탑에서 보여지기 위해서는 한눈에 섹션이 보여질 수 있도록 구성해야 될 것을 알게 되었으며 디자인을 시작할 때 화면의 구성과 여백의 px설정을 화면에 섹션이 담아질 수 있도록 설정할 필요가 있음.
